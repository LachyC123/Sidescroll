# CROWNLESS

A pixel-art action-platformer built from Anokolisa's Legacy Fantasy Complete
Collection, following the staged production contract in
`Legacy_Fantasy_Sidescroller_AI_Master_Plan.docx`.

The royal road has been severed. A nameless sword courier wakes in the High
Forest carrying the last ember of the Crown Bell, and walks fifteen environments
to the capital, relighting waystones as they go.

## Run it

No build step, no dependencies. Serve the repo root and open the game:

```sh
python3 -m http.server 8099
# then open http://localhost:8099/game/
```

It is also deployed to GitHub Pages on every push to `main`:
`.github/workflows/deploy-pages.yml` publishes `game/` as the site root, with
no bundler involved.

It must be served over HTTP rather than opened as a `file://` URL, because the
game loads its data as ES modules and `fetch`es its manifests.

**Controls** — arrows or WASD to move, `Space`/`Z` jump, `J`/`X` attack,
`C` heal, `E` interact, `Esc` pause, `Tab` road map. A gamepad works throughout
and prompts change glyph the moment you touch one. Everything is rebindable in
Settings → Controls.

## What is in it

| | |
|---|---|
| Engine | Canvas 2D, 384×216 internal canvas, integer scaling, nearest-neighbour only |
| Campaign | 15 environment chapters + epilogue, every pack given a real role |
| Enemies | 8 asset-backed silhouettes, 5 phase-based boss encounters |
| Pressures | falling branches, gusting wind, poison, water, darkness, rain |
| Economy | Road Ash buys Vow tiers at waystones; 27 fixed Health Fragments |
| UI | boot, title, 3 save slots + autosave, pause, road, vows, journal, settings, accessibility, rebinding, death, chapter complete, credits |
| Audio | fully synthesised at runtime with WebAudio — no audio files ship in the collection |

## Layout

```
game/                 the game. index.html + src/, no build step
  src/core/           screen, input, audio, save, settings, text, assets, rng
  src/render/         camera, tilemap, parallax, vfx
  src/game/           player, enemy, world, compose, chapters, tuning, hud
  src/ui/             menu framework and every screen
  assets/             normalised art, generated by tools/build_assets.py
  data/               tilesets, props and the runtime asset manifest
tools/                asset pipeline, self-containment check, verification harness
tests/                unit tests for the standalone ZIP audit
docs/                 Gate 0 outputs, tuning notes, gate log, evidence shots
*.zip                 the original collection, never modified
```

## Rebuilding the assets

The ZIPs in the repo root are the archive of record and are never touched.
Everything under `game/assets` and `game/data` is generated:

```sh
python3 tools/build_assets.py     # extract, recover, normalise, write manifests
python3 tools/classify_tiles.py   # derive autotiling roles for all 15 tilesets
python3 tools/extract_props.py    # find placeable objects in the prop sheets
```

`tools/audit_assets.py` is a separate, deterministic inventory of the raw ZIPs,
run in CI by `.github/workflows/gate-0-asset-audit.yml`. It overlaps the
pipeline above but is kept as an independent cross-check on the archives.

`tools/aseprite.py` is a minimal `.aseprite` decoder. It is not optional:
Scarlet Monastery's only background, Muddy Swamp's tree, Kingdom Fortress's
city sheet and Deadwind Pass's bones exist nowhere else in the collection.

## Verifying

```sh
python3 -m http.server 8099 &
node tools/verify.mjs
```

This drives the real game in Chromium — boot, menu navigation by keyboard,
movement, jump, attack, combat resolution, traversal, pause, death, respawn,
save, reload, continue, boss phases, per-enemy reachability, the wind and
falling-branch hazards, fragment quotas, the vow altar and the Chapter 5
disarmed opening — and asserts that all 16 chapters compose with ground,
checkpoints and decoration. It writes screenshots to `shots/`; the copies in
`docs/evidence/` are the Section 12 gate evidence.

Requires `playwright` (`npm i playwright`); it uses the pre-installed Chromium
rather than downloading one.

## Production rules

From the master plan:

- Preserve original archives.
- Inspect before slicing.
- Greybox before decorating.
- Keep pixel rendering nearest-neighbour and grid-consistent.
- Keep the HUD compact.
- End every gate with runnable evidence and review.

## Honest status

This is a complete, playable title-to-credits game. It is not a
finished commercial product, and the master plan is clear about the difference.
What is still outstanding is recorded in
[`docs/asset_issues.md`](docs/asset_issues.md) and
[`docs/gates.md`](docs/gates.md); the short version:

- **Boss art.** Section 6's art gate forbids scaling a normal enemy and calling
  it a boss. The five bosses are real pattern encounters with phases, but they
  are built on existing silhouettes at native scale and still need dedicated art.
- **Player animation.** The collection ships one attack, not two, and no hurt,
  landing, interact or heal frames. Attack 2 is a committed timing variant of
  the single clip; hurt is a derived flash. Dodge, aerial attack, crouch,
  ladders and blocking are deliberately absent because their art is.
- **Enemy variety.** Eight silhouettes across fifteen chapters. Section 6 wants
  at least fifteen. Biome pressures and variants carry the difference for now.
- **Playtesting.** The Section 13 release checklist asks for five first-time
  tutorial playtests and two full completion passes by humans. None have
  happened.
